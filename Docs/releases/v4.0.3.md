### Download

Self-contained: unpack one and run `./ironruby`, `./irb.sh` and `./igem.sh` - on Windows
`ironruby.cmd`, `irb.cmd` and `igem.cmd`. No .NET to install. Or, on Windows, run the
installer.

- **Windows x64 installer**: `ironruby-4.0.3-win-x64-setup.exe`, the zip below, installed
  into `C:\IronRuby40-x64` and put on the PATH
- **Windows x64**: `ironruby-4.0.3-win-x64.zip`, with Windows Forms, WPF, `ironrubyw.exe`
  and `Samples\Notepad\notepad.cmd`
- **Linux x64**: `ironruby-4.0.3-linux-x64.tar.gz`
- **macOS arm64**: `ironruby-4.0.3-osx-arm64.tar.gz`, built in CI, not tested there

`SHA256SUMS` lists the checksums. Each file and `SHA256SUMS` has a signed build
provenance attestation, which says which workflow built it, from which commit, in which run:

```
gh attestation verify ironruby-4.0.3-win-x64-setup.exe --repo Largo/ironruby
```

### New

- **A Windows installer**, in the style of RubyInstaller. It installs the win-x64 zip's
  tree, unchanged, into `C:\IronRuby40-x64` by default, or a directory you choose, for you
  alone (no admin rights) or for all users, and puts that directory first on the PATH, so
  `ironruby`, `ir`, `irb` and `igem` work from a new terminal. `igem install` writes into
  the install tree, which is why the default is a directory you can write to and has no
  space in its path: Bundler's `RUBYOPT`, the Rails templates and mspec break on one.
  Running `.rb` files with IronRuby is an option, off by default. The uninstaller removes
  the files, the gems installed since, and the PATH entry. It is built in CI with Inno
  Setup 6.7.3 from `Util/installer/ironruby.iss`, and installed, run and uninstalled there
  before it is published.

### Changed

- **`ironruby` at a terminal starts irb**, as `python` starts its interactive interpreter:
  with no script and no `-e`, and stdin a terminal, `ironruby` is `iirb`. From a pipe or a
  file it still reads the program from stdin, as `ruby` does, and so do `ironruby -`,
  `-n`, `-p`, `-c` and `-x`.
- **IronRuby no longer uses a CRuby's gems.** It used to offer the gem directory of a CRuby
  4.0 found on the PATH for third-party gems. That loaded CRuby's code into IronRuby: with
  CRuby on the PATH, `igem install` loaded CRuby's rdoc plugin over the rdoc IronRuby ships
  ("already initialized constant RDoc::VERSION") and then failed generating the gem's
  documentation. IronRuby now reads only its own gem directories; a gem it needs is
  installed for it, with `igem install` or Bundler. `IRONRUBY_NO_HOST_GEMS` is gone with it.
- **`igem install` builds no documentation unless asked**, as on TruffleRuby: generating ri
  and rdoc takes longer than installing most gems. `igem install --document` (or
  `gem: --document` in `~/.gemrc`) builds it with the rdoc IronRuby ships, and uninstalling
  the gem removes it again.

### Fixes

- **irb starts on Windows again.** In 4.0.2 it stopped at once with `unknown symbol
  "FillConsoleOutputCharacter"`. reline asks Fiddle for Win32 functions by their bare
  names, and Fiddle now also looks for the `A` export, as CRuby's does. In a console, irb
  then crashed: reline hands the console API its buffers as `[str].pack("p")`, and on
  IronRuby that was an index, not an address. It is a real address now, of a block holding
  the String's bytes, and what C writes there through Fiddle comes back into the String, as
  with CRuby - so reline runs as Ruby ships it.
- **irb shows results on Windows.** After the first result it stopped with
  `Errno::ENOTTY` from `IO#winsize`: IronRuby's io/console asked only termios for the
  terminal size, which Windows does not have. It now asks the console, as CRuby does, and
  raises `Errno::EBADF` off a console, as CRuby does on Windows.
- **`require 'ripper'` gives `Ripper::Filter`**, as in CRuby. rdoc's Ruby parser subclasses
  it, and generating a gem's documentation failed with `uninitialized constant
  Ripper::Filter`.
